\section{Task description/Problem statement}

To an average reader, Latin \texttt{a} and its Cyrillic lookalike will appear identical. To a machine learning classifier, their code points U+0061 and U+0430 are different inputs. Invisible characters create the same problem without replacing a visible letter. A familiar word can lose its vocabulary entry or split into unusual subword tokens even when its meaning remains easy to recognize to a human reader.

I studied how this mismatch affects short-text classification and whether inexpensive preprocessing can repair it. The central comparison uses the same Logistic Regression approach and changes its representation: word, character or BPE TF--IDF. DistilBERT adds a contextual, pretrained comparison. Every system receives the same perturbed examples.




The analysis follows three questions: how quickly performance falls as the attack budget grows, which transformations cause the largest failures, and how much of the lost performance input repair can recover.

The task is to assign one label to a short input text: a banking intent for BANKING77 or an answer type for TREC. After a Unicode attack, the expected label stays the same. I check whether the classifier still predicts it and whether simple input repair helps.

\subsection{Examples}
These are two real inputs from the test sets:
\begin{itemize}
\item BANKING77: ``How do I locate my card?'' $\rightarrow$ \texttt{card\_arrival}.
\item TREC: ``How far is it from Denver to Aspen ?'' $\rightarrow$ \texttt{NUM}, a numerical answer.
\end{itemize}

\subsection{Real-world applications}
Intent classification can route a banking request to the right support flow. Question classification can guide a question-answering system toward a person, place, number or another answer type. Unicode changes can also matter in content moderation, where text may be deliberately obfuscated. I focus on the first two tasks here; they let me compare robustness without changing the intended meaning of an example.
