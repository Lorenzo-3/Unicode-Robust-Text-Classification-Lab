\section{Qualitative Error Analysis}

The analysis selects cases using declared rules rather than hand-picking: the largest gold-label probability loss among successful attacks, the largest probability recovery after preprocessing, and high-disruption attacks that do not change the prediction. Tables show both rendered text and escaped code points because invisible modifications cannot be audited visually.

The successful BANKING77 example replaces letters in ``There is a suspicious direct debit payment'' with Cyrillic or related lookalikes. The word vocabulary loses several lexical cues and predicts the wrong intent; the restricted confusable repair reconstructs the clean ASCII string and restores the prediction. By contrast, the invisible attack on ``Do you offer Visa or Mastercard?'' inserts five default-ignorable controls but does not overturn the selected model prediction. Such resisted cases matter: attack strength counts code-point edits, not guaranteed semantic-feature removal, and redundant class cues can survive substantial local disruption.

The same rendered sentence can therefore represent three distinct computational cases: a failed raw classifier, a repaired classifier, or a classifier that was robust without preprocessing. Reporting only successful examples would exaggerate vulnerability, while reporting only aggregate scores would hide why recovery occurs. The modification log and escaped display make both outcomes reproducible even when the terminal, PDF viewer, or font does not visibly render the inserted characters.
